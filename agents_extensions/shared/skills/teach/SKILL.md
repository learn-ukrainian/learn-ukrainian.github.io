# Teach

Explain the thing so a reader understands it. The explanation is the deliverable, not a report about the explanation.

1. Say what it is, in one sentence, from the reader's point of view.
2. Walk one concrete path through how it works (`how`).
3. Say why it is this shape, from the repository record (`why`). Label a motive you cannot source as unknown.
4. Stop at the boundary of the question. Do not expand into a redesign.

Use short sentences. Define a project term the first time. Do not invent a diagram you did not derive from the code.
