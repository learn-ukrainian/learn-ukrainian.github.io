# Technical writing

Pick the mode before the prose. Then write sentences a reader can use. Run `unslop` on the draft before you call it done.

| Mode | Job | Leave out |
| --- | --- | --- |
| Tutorial | The reader builds one thing. You own their success. | History and asides |
| How-to | Steps to a goal the reader already has. | Teaching the basics |
| Reference | Facts for lookup: options, limits, errors. | Instruction and opinion |
| Explanation | Why, one bounded topic. | A procedure |

- Cut a word the sentence survives without.
- Use the short everyday word when it is precise.
- One idea per sentence. Name the actor.
- A heading is sentence case.
- Do not open with a slogan. Lead with the outcome or the fact.
- Repository prose follows the repo's voice: plain, tool-backed, no secrets, no host paths.

A rule that makes a sentence worse yields to a clearer sentence. Do not copy a style guide in place of the document.
