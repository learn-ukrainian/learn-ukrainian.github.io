# Experience first

When implementation convenience conflicts with the consumer's experience, choose the experience. The consumer is the learner, the caller of a library, or the next engineer who must change the code.

- Every feature, control, and option has to justify itself.
- Ship fewer polished behaviors rather than more rough ones.
- A throwaway prototype is cheaper than a production guess when the decision is about feel (`principle-exhaust-the-design-space`).
- Get the visible details right: feedback, errors, alignment, and the main loop.
- A feature that does not serve the main task gets out of the way.

Foundations decide the sequence of work (`principle-foundational-thinking`). This principle decides the target.
