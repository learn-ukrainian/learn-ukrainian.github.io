# Figure it out

Use this when no `poteto-mode` playbook fits the task. Design the procedure. Do not install it as a new standing process.

1. Frame the exit condition as something a later run can check. Name non-goals.
2. Pick the smallest existing playbook steps that apply. Add a step only for a gap.
3. Run the procedure inside the brief, one verifiable unit at a time (`principle-sequence-verifiable-units`).
4. Record decisions with `show-me-your-work` when the task will be reviewed later.
5. Hand back the procedure, what the check showed, and what is still open.

If the procedure needs a new architecture or a new control plane, stop for designated approval. A worker does not dispatch the procedure onward.
