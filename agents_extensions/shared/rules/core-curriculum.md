# Rules core — content-seat addendum

<critical>

Loaded with `core.md` by curriculum seats only (planning, writing, reviewing, building modules).
Each comment gives an anchor and its lead inventory unit; `core-manifest.yaml` maps every unit.

- Non-negotiables are hard gates: every audit gate green. Diagnose all module issues first, repair them all together, and verify once. <!-- ca-gates: N01 -->
- Accept content when every plan objective and content point is taught accurately, with sufficient explanation for the intended learner, useful worked examples, and aligned practice with feedback. Require explicit connections between ideas and explanations of unfamiliar terms, steps and reasoning. Reject missing coverage, unsupported claims, repetitive padding, decorative digressions, dry lists replacing teaching, and compression that forces learners to infer untaught connections. Judge length by what the teaching requires; neither reward nor penalize a word count. Never silently modify plan files or stage plan `.yaml.bak` files. Only VESUM-failing `vocabulary_hints` may be auto-fixed, with a version bump and `plan_fixes` log. Preserve activity, variety, vocabulary and naturalness requirements in their owning contracts. Report unsupported objectives or evidence gaps for research or versioned plan review; never auto-pad. <!-- ca-targets: N02 -->
- Apply `docs/best-practices/strict-reviewer-persona.md`: run every review dimension as an independent model call with its own strict persona; never bundle dimensions into one pass. Aggregate by minimum, not weighted average, and preserve the minimum-dimension gate and its PASS, REVISE and REJECT thresholds (PASS ≥ 8, REVISE < 8, REJECT < 6; target 9). Reviewers read the content and cite examples, grammar, vocabulary and facts; rewrite unnatural text. <!-- ca-review: N14 -->
- Zero Russian ghost words; dialogues from natural textbook situations. The writer generates `словник` YAML with contextual translations; verify every vocabulary word through VESUM. Every plan must contain a `references` field with textbook and ULP links; no plan ships without it. Stress marks come from the deterministic annotator after review, never the writer. <!-- ca-language: N15 -->
- Activities test Ukrainian, not subject recall: if the learner can answer without reading the Ukrainian, rewrite (language-mechanics items exempt). A1 landing cards use bilingual `title`/`titleEn` and `sub`/`subEn`; `lessons.yaml` titles and generated `index.mdx` are bilingual and match taught content. A1.1 modules 1–4 place English beside every learner-facing stem, option and explanation. From `who-am-i`, use Ukrainian-first standard A1 support. Deferred left-navigation work must not block module PRs. <!-- ca-activities: N26 -->
- Before requesting more pedagogical material, read `docs/corpus-inventory.md`, inspect existing reference, textbook-text and textbook-data stores and query `mcp__sources__search_text`. Follow source-specific methodology: the operator's private pedagogy references (permissions register id `ulp_private`: ULP lesson notes, Anna Ohoiko's books) are grounding-only, never copied, quoted, presented as source text or used as a card field source. Methodologically permitted incidental constructs may precede explicit teaching. When creating JSONL data, add its ingestion flag to the script and update `DICTIONARY-PIPELINE-STATUS.md` in the same commit. Verify that a module's MDX is nonempty and every tab renders. Do not add a test file or test case unless the CTO approves that specific test. Build one module, verify pedagogy, then proceed; prove one working end-to-end example first and trace pipeline inputs before modifications. Use textbook-grounded dialogues and explain each teaching point fully, without padding or compressed under-explanation. The general testing requirements (no new tests without CTO approval, 80% critical-path coverage, Ruff before CF) bind in the always-loaded core. <!-- ca-proof: Y18 -->

</critical>
