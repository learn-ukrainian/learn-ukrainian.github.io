# Rules core — content-seat addendum

<critical>

Loaded with `core.md` by curriculum seats only (planning, writing, reviewing, building modules).
Each comment gives an anchor and its lead inventory unit; `core-manifest.yaml` maps every unit.

- Non-negotiables are hard gates: every audit gate green. Diagnose all module issues first, repair them all together, and verify once. <!-- ca-gates: N01 -->
- Legacy module workflows (`non-negotiable-rules.md` rule 1 scope) read targets from `scripts/audit/config.py` before outlining or budgeting; never hardcode. Targets are minimums: meet words (sections ±10%), activity, variety, vocabulary and naturalness thresholds with source-backed pedagogy; when content falls short, expand it; never lower, repeat, auto-pad or silently alter targets. Never silently modify plan files, lower `word_target` to match output, or stage plan `.yaml.bak` files. The pipeline may auto-fix only VESUM-failing `vocabulary_hints`, with a version bump and `plan_fixes` log. Content outlines, objectives and word targets remain immutable. Overshoot is not padding. When grounding runs out, emit `SIZE_POLICY_MISMATCH` for plan review. Core fresh-build lessons are sized by their own contracts (rule 4), not by these `config.py` word, section, activity, variety or vocabulary minimums, nor by overshoot; only sizing is scoped, and the plan-file, source-backed pedagogy and naturalness duties above still bind every workflow. Rule 1's anti-padding duty binds every workflow: content meets any word target only with source-backed necessary pedagogy, never by repeating exposition or auto-padding. <!-- ca-targets: N02 -->
- Apply `docs/best-practices/strict-reviewer-persona.md`: run every review dimension as an independent model call with its own strict persona; never bundle dimensions into one pass. Aggregate by minimum, not weighted average, and preserve the minimum-dimension gate and its PASS, REVISE and REJECT thresholds (PASS ≥ 8, REVISE < 8, REJECT < 6; target 9). Reviewers read the content and cite examples, grammar, vocabulary and facts; rewrite unnatural text. <!-- ca-review: N14 -->
- Zero Russian ghost words; dialogues from natural textbook situations. The writer generates `словник` YAML with contextual translations; verify every vocabulary word through VESUM. Every plan must contain a `references` field with textbook and ULP links; no plan ships without it. Stress marks come from the deterministic annotator after review, never the writer. <!-- ca-language: N15 -->
- Activities test Ukrainian, not subject recall: if the learner can answer without reading the Ukrainian, rewrite (language-mechanics items exempt). A1 landing cards use bilingual `title`/`titleEn` and `sub`/`subEn`; `lessons.yaml` titles and generated `index.mdx` are bilingual and match taught content. A1.1 modules 1–4 place English beside every learner-facing stem, option and explanation. From `who-am-i`, use Ukrainian-first standard A1 support. Deferred left-navigation work must not block module PRs. <!-- ca-activities: N26 -->
- Before requesting more pedagogical material, read `docs/corpus-inventory.md`, inspect existing reference, textbook-text and textbook-data stores and query `mcp__sources__search_text`. Follow source-specific methodology: the operator's private pedagogy references (permissions register id `ulp_private`: ULP lesson notes, Anna Ohoiko's books) are grounding-only, never copied, quoted, presented as source text or used as a card field source. Methodologically permitted incidental constructs may precede explicit teaching. When creating JSONL data, add its ingestion flag to the script and update `DICTIONARY-PIPELINE-STATUS.md` in the same commit. Verify that a module's MDX is nonempty and every tab renders. Every bug fix includes a regression test that catches that same bug. Build one module, verify pedagogy, then proceed; prove one working end-to-end example first and trace pipeline inputs before modifications. Use textbook-grounded dialogues; in legacy module workflows, draft toward the stated 1.5× word-target overshoot before trimming (fresh-build lessons follow their own sizing contract). The general testing requirements (every changed function tested, 80% critical-path coverage, Ruff before CF) bind in the always-loaded core. <!-- ca-proof: Y18 -->
