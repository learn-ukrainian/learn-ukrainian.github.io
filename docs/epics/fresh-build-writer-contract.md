## What is already decided (plan schema §5 and §7.1, R-26, R-12, R-22, R-35)
The writer receives exactly four things: the lesson's plan entry; the evidence records that entry cites; the learner state for that position with its immersion rule; the fixed style card. One call per lesson. It does not search. Steps, their order, their evidence and their activities are binding; only the wording inside a step is the writer's. The recap writer also receives the built lessons 1…N−1 of its module.

## Principles
1. **The writer returns data, not a page.** One structured document per call, validated by a schema before anything else looks at it. The engine assembles the four tabs from it; nobody interprets prose to find a step, an activity or a citation.
2. **The writer never produces a fact about Ukrainian that a record already holds.** It does not type a stress mark, a gloss, a translation of a cited example, a source line for Ресурси or a vocabulary card. The engine takes each of these from the word store and the pack. What is left to the writer is what only a writer can do: explain, connect, build situations, write dialogue and activity items inside the inventory.
3. **Stop, do not improvise.** Missing evidence is reported as a gap and routed to the layer that owns it (R-12). A lesson with an open gap is not a lesson.
4. **Nothing about itself.** No commentary on its process, no self-assessment, no notes to the reviewer. The output schema has no field for it, and the reviewer contract (#8430) relies on that.
5. **Honest guarantees (r3).** Every check in this contract is labelled by what it proves. A schema can prove a document's shape and its declared gaps; it cannot prove a model told the truth about a gap it concealed. Concealed gaps are the reviewer's to find (#8430 Contract 2 point 5) and the seeded-defect set plants them.

## 1. Output contract — `lesson-draft-v1`
```yaml
draft_schema: 1
lesson: { module: a1/<slug>, n: 2 }
inputs: { plan_sha256, pack_lock, words_lock, lesson_lock_entry_sha256, learner_state_sha256, style_card_sha256 }   # echoed back; the engine refuses a mismatch
status: ok | evidence_gap
steps:                         # exactly the plan's step ids, in the plan's order
  - id: s1
    lead_in: "…"              # optional: one or two sentences that carry the thread from the step before
    blocks:                    # the writer's wording lives only here
      - { kind: prose, text: "…", explains: [T-003] }       # `explains`: the records this explanation rests on (r3, see §1a)
      - { kind: example, ref: EX-001 }                      # by id; the engine prints text, stress, translation
      - { kind: quote, ref: T-007 }                         # verbatim from the pack, attributed by the engine — the only block that prints source prose
      - { kind: paradigm, ref: P-01 }                       # a table of forms: specified in the plan entry (the engine keeps the plan's `paradigm` spec: word id, form tags, row order), generated from the word records
      - { kind: table, rows: [[…]], explains: [T-003] }     # non-paradigm tables only (a schedule, a comparison of uses)
      - { kind: pronunciation, text: "…", explains: [T-005] }
      - { kind: bilingual, uk: ["…"], en: ["…"] }             # side-by-side passage; A1–A2 only, where the immersion rule allows; `uk` and `en` have equal length, aligned line by line
      - { kind: culture, text: "…", explains: [T-011] }      # a fact about Ukraine always carries its record
      - { kind: tip, text: "…" }                            # tip / summary / callout: connective prose; may not carry a language or culture claim (§6) — a claim needs a block with `explains`
      - { kind: summary, text: "…" }
      - { kind: callout, text: "…" }
      - { kind: video, ref: V-002, lead_in: "…" }
      - { kind: dialogue }                                  # placed once, in the step whose id the plan's `dialogue.step` names (plan schema addition, §1b)
      - { kind: activity, ref: a1 }                         # exactly the plan's `practice` ids, in order
consolidation: { lead_in: "…", activities: [a5, a6, a7] }   # equals the plan's list
dialogue:
  lines: [ { speaker: Оксана, text: "…" } ]                 # speakers exactly as the plan names them
  translation_en: [ "…" ]                                   # one entry per line, or absent as a whole, per the immersion rule
activities:
  - id: a1                    # id is the plan's; `type` and `placement` are NOT repeated here — the engine takes them from the plan (§2)
    instruction: "…"
    items: [ … ]              # the item shape is the PER-TYPE schema of `schemas/activities-<level>.schema.json` (§1c) — not a generic item
gaps: []                      # see §4; non-empty only with status: evidence_gap
```
Not in the draft, because the engine generates them: **Словник** (from the lesson's `core` and `incidental` records: stressed lemma, authorised forms, gloss, Atlas link), **Ресурси** (from every id cited in the draft, with the pack's source data), the practice deck (R-33), the landing-page numbers (scope sidecar), **inline glosses** (§1d), stress marks (§3).

### 1a. Evidence use, precisely (r3 — replaces "coverage with grounding")
r2 required a `T-` record's quoted text to appear verbatim in any step it grounds. That forced source prose onto the learner page regardless of its vocabulary or length, could conflict with the allowlist and the short theory step, admitted a vacuous pass (paste the quote beside a wrong explanation), and assumed a publication right the pack does not record. r3 separates the two things a citation can mean:
- **`explains: [ids]` on a prose/table/pronunciation/culture block** says: this explanation rests on these records. The coverage gate checks **set arithmetic**: for each step, the union of `explains` and `ref` ids ⊇ the ids the plan's step lists; for the lesson, nothing cited that the plan does not list; every cited id is printed in Ресурси with attribution. Whether the explanation is *supported* by the record is the reviewer's `evidence_use` dimension (#8430) — R-28's "used and cited" means this mapping plus Ресурси, not verbatim inclusion.
- **`quote` blocks** are the only place source prose reaches the page. The engine prints the pack's `quote` bytes exactly (verbatim check against the record, before stress annotation, NFC-normalised), attributed. A plan that wants a quote on the page lists the record and the step; the writer places the block. **Publication right (r3):** the pack's source metadata (`kind, file, grade, author, page`) records provenance, not permission; before the first module is published the corpus lane records, per source, whether excerpts of the length we print may be published and under what attribution (a `publish: { allowed: bool, limit_chars, attribution }` field on the source registry, read by `pack-verify`). Until a source carries it, a `quote` block from that source is a gap (`need: publication_right`), and the plan cites the record through `explains` only. This is a new prerequisite, filed in the build program; it is not a licence finding.
- `example`, `error`, `video` and `paradigm` reach the page only by `ref`, printed by the engine from the record, so they cannot be cited without being used.

### 1b. Plan-schema additions this contract needs (a small revision 9 of the plan schema, docs PR)
- `dialogue.step: <step id>` — the step that hosts the dialogue (r2 said "the step the plan names"; the plan had no such field).
- `steps[].paradigm: { id: P-01, word: W-042, forms: [<form tags>] }` — as r2 proposed; the engine generates the table from the word record in that order.
- `steps[].needs: [example | quote | error | video | culture | paradigm]` — the **declared demand** of a step, so that the preflight (§4) can check that the records a step needs exist; r2's "each step has the records its kind needs" had no executable demand.
- `activities[].error_refs` moves to the plan as a requirement (`type: error-correction` ⇒ the plan lists the `E-` ids the activity may draw on) and the draft binds each **item** to one of them (§1c).

### 1c. Activity items — the existing per-type schemas, not a generic item (r3)
The repository already has per-type item schemas: `schemas/activities-<level>.schema.json`, keys `<type>-<level>` (A1: 20 types). The draft's `items` for an activity of type `t` must validate against the `t-<level>` definition **as it stands** (the Codex seat showed r2's example fails it: A1 quiz uses `correct` as an integer or `answer` as a string, and `explanation`, not `explain`; match-up uses `pairs`; error-correction requires `sentence`, `error` and a correction). `lesson-draft-v1` therefore does **not** define item shapes; it references those definitions by `$ref`, and the writer is told the exact item shape per type in its prompt (rendered from the schema, not typed). Two additions, made to the level schemas by a docs-and-schema PR before the pilot: (1) every item type gains a required non-empty `explanation` where it lacks one (this absorbs #8214); (2) error-correction items gain `error_ref: E-…` (required), whose record's `incorrect` text must appear in the item's `sentence` and whose `correct` text must be the item's correction — the gate checks both; whether the error applies in this context stays the reviewer's. Distractors and error text are **typed fields** of these schemas; the inventory and spelling checks skip them by field (the schemas already mark such fields, e.g. `vesum_exempt`), so an intentionally wrong form in an error item is never a `lemma_outside_state` failure. **Stress exercises (R-33):** the item schema for stress practice carries the word id and the engine generates the stressed alternatives from the record; the writer never writes stress alternatives.

### 1d. Inline glosses (r3)
The plan requires `incidental` words to be glossed inline (§2). The writer may not type a gloss. So the draft marks the span: in any text field a token may be wrapped as `[[W-040]]`-style reference (`{{gloss:W-040}}` — exact syntax fixed by the schema), and the engine prints the word and its gloss from the record. A gloss reference to a record outside `incidental` (or outside `core` on its first occurrence) fails the schema gate. This is the only inline markup the writer may use besides the quoted-term span of §6.

## 2. Steps are binding — how a gate checks it
The draft is keyed by step id, so there are no boundaries to detect. The `structure` gate checks: the step ids and their order equal the plan's; each step's `activity` refs equal the plan's `practice` list in order; `consolidation.activities` equals the plan's; the dialogue block sits in exactly the step `dialogue.step` names; `type` and `placement` are taken from the plan for every activity (the draft does not carry them); no block kind outside the list above; `bilingual.uk` and `.en` equal in length; `dialogue.translation_en` equal in length to `lines` or absent.

## 3. Words and stress
- **The writer writes plain Ukrainian text without stress marks.** A combining accent (U+0301, U+0300) anywhere in a draft fails the schema gate. Apostrophes are normalised by the engine to the word store's one convention before anything is matched.
- **The resolver, with its proof boundary stated (r3).** The engine tokenises every Ukrainian string of the **expanded** learner-facing document (writer strings plus every engine-printed block — quotes, examples, paradigms, glosses, vocabulary cards, resources — because a reference block adds text the writer never typed) and, for each token, records a **resolution**: the candidate analyses from VESUM and the word store, the features that all candidates share, the selected record and form, and **how** it was selected. What tags can prove without a model is small and is stated as such: VESUM gives a preposition only `prep` — no governed case (the Codex seat's query: `у, в, з, зі, із` → `prep`); the word store's `government` is a sourced string, not an executable constraint; the tag map (`scripts/curriculum/evidence/tags.py`) interprets atoms within one analysis and does not look at neighbours. So the deterministic narrowing is: candidates restricted to records in the allowlist (planned state ∪ `core` ∪ `incidental`, #8414), then the features common to all remaining candidates. Everything beyond that — agreement with a neighbour, the case a preposition governs, sense — is **a model's judgement**, and the contract says so: it is not a proof.
- **Three kinds of ambiguity, three treatments (r3).** After deterministic narrowing a token is one of: **(i) resolved** — one record, one form, one stress; **(ii) stress-certain, identity-uncertain** — several records or forms share the stress (the Codex seat's measurement on ULP lesson 10: 41 of 91 tokens had several VESUM analyses, 11 several lemmas, and only 1 a remaining stress ambiguity); the printed stress is safe, but the **record identity** decides the gloss, the Atlas link, the observed state and the digest's sense — so it is asked as a constrained question too, but **after** the cheap checks and batched per lesson; **(iii) stress-uncertain** — the readings differ in stress (`за́мок` / `замо́к` share tags; `verify_stress` returns both with `unresolvable_by_tags`); asked as a constrained question before any stress is printed. A **constrained question** is: the sentence, the token, and the two or three enumerated candidates from the word store; a language-lane seat picks one; the answer is a **resolution receipt** (below). A statistical tagger (Stanza, in `scripts/pipeline/stress_annotator.py`) may **propose** an ordering of candidates, never decide: that annotator's repair path that takes `matches[0]` for an unstressed ambiguous word (`stress_annotator.py:170`) is exactly what the engine must not inherit, and its tokenizer splits hyphenated compounds the oracle handles whole — the new resolver tokenises with the oracle's word boundary. How many tokens need a question is measured in the pilot; the one number we have (1 stress question in 91 tokens on a real lesson, before allowlist narrowing) says the rate is low, not zero.
- **Resolution receipts (r3).** Every token resolution — deterministic or asked — is stored beside the built lesson (`_state/lesson-<n>.resolutions.yaml`, deterministic YAML, lock sidecar): token occurrence (tab, unit, offset), candidate set, selected record and form, decision provenance (`deterministic | question:<seat> | proposal:<tagger>+question`), and the input hashes. The reviewer sees the asked ones as resolved ambiguities and may contest them; the observed-state index (#8414) and the digest (#8430) read the record ids from here, never from a re-analysis.
- **The engine never guesses a stress.** A cited or used form whose `stress_source` is `pending` stops the build before the call (R-23); the preflight checks the forms the plan **cites** and, after the draft, the gate checks every form the lesson **uses** — not every form of every admitted paradigm (plan schema §3, "a lesson whose built text uses a form that is still pending").
- **Source markers (r3).** "Any form of an allowed lemma" means any form the word record marks `learner: true`; a form carrying an excluding marker (`alt, arch, bad, dialect, obsc, slang, subst, vulg` — `scripts/curriculum/evidence/codes.py`) is in the record for completeness and is **not** an allowed form: the resolver treats a token whose only analyses are marked forms as `lemma_outside_state`.
- **Surface categories (r3).** The resolver classifies before it resolves: ordinary sentence tokens (resolved as above); single letters and syllables in literacy lessons (`phonetics` items — matched to the plan's letters, never looked up as words); hyphenated compounds (one oracle token); typed error text and distractors (skipped by field, §1c); quoted terms inside English narration (§6); proper nouns (word records with case forms — the plan's speakers and places; a name without a record is `lemma_outside_state`). An unclassifiable token fails.

**Which forms may the writer use — DECIDED by the operator, 2026-09-21:** *"allow yes, if something is have not tought yet the student has to memorize it. it is normal. later he will learn about it."* A writer may use **any form of an allowed lemma** that the sentence needs, whether or not the learner has been taught that form's category (subject to the source markers above).
- **Lemmas stay restricted, forms do not.** The allowlist is planned state + this lesson's `core` and `incidental`, by word record; the inventory gate fails an unknown **lemma**, never a learner-usable form of a known one.
- **An untaught form is used, not explained.** No table, no rule, no terminology for a category the arc places later. The reviewer's learner-fit check (#8430) watches sentence length, clause depth and the share of untaught forms.
- **The plan's per-word `forms` lists stay**, with a different job: the forms this lesson commits to teach and drill, and the ones the practice deck takes. The gate checks that each listed form **appears in a teaching or drilling position** (a paradigm table, an activity item, or the step that introduces the word) — a mere occurrence anywhere does not count (r3).
- **Cost, stated plainly:** the word store holds the **full paradigm** of every allowed lemma, each form with its stress (R-22).

## 4. When the evidence is not enough
**Most gaps are found before the call, by script — availability, not adequacy (r3).** The preflight checks that each step has the records its declared `needs` (§1b) call for: an error-correction activity its `E-` records, an `example` need its `EX-`, a `paradigm` its word's forms with non-pending stress, a `video` its `V-`, a `culture` need its `T-`, a `quote` its record with a publication right (§1a). It proves existence, type, lock integrity and required fields. It cannot prove that a quote supports the explanation, that an example shows the intended contrast, or that the allowlist supports the situation naturally — those gaps only a writer or a reviewer can see. For what only the writer can see, it returns `status: evidence_gap` with
```yaml
gaps: [ { step: s2, need: example | quote | error | word_form | video | standard_line | publication_right, detail: "One sentence: what is missing and for which teaching point." } ]
```
**Executable invariants (r3):** with `status: evidence_gap`, `gaps` is non-empty, every `gaps[].step` is a plan step id, and the blocks of **exactly** those steps are empty; with `status: ok`, `gaps` is empty and no step is empty. Any other combination fails the schema gate. What the schema **cannot** catch: a writer that returns `status: ok` and fills a step from memory. That is a concealed gap; the reference checks (an `example` must be a `ref`, a fact must carry `explains`) narrow where it can hide, the reviewer's `evidence_use` and `fact` dimensions are where it is found, and the seeded-defect set plants it. The driver routes a declared gap to the pack builder (or to the plan, if the plan asked for something the sources do not have).

## 5. The fixed style card
One versioned, hashed document per band (A1, A2, B1+ — operator decision 3); its hash is echoed in every draft and recorded in every review. It holds what is true of **every** lesson; anything true of one lesson belongs in the plan.

| In the card | In the plan |
| --- | --- |
| The presentation practices of `docs/best-practices/ulp-presentation-pattern.md`, stated as rules for our own voice: Ukrainian first with the gloss after; side-by-side support for A1 passages of three or more sentences; dialogue in Ukrainian only with the translation after it; comprehension questions in Ukrainian; translation tasks only in the workbook | which steps, which evidence, which activities, which words |
| **Voice:** no named narrator, no self-introduction, no imitation of another author's persona; named people only inside dialogues; a quotation is marked, attributed and listed in Ресурси | the dialogue's situation, setting, speakers, register |
| **Conversational rules (r3):** what a natural exchange does at this level — question and answer adjacent, elliptical answers where Ukrainian allows them, reciprocal questions, confirmation turns, memorised phrases used as they stand, `ти`/`ви` consistent with the speakers' relationship, agreement with the speaker's gender — stated as rules, with the reviewer's dimension named for each | the exchange's purpose and participants |
| The textbook lesson shape (R-27): a small theory step, then its practice, then the larger block | the `job`, the `rationale`, the word target |
| Activity writing rules (R-19): one defensible answer for single-answer types; plausible distractors; an instruction in the language the immersion rule gives; no answer leaking from a neighbouring item; an `explanation` for every item | each activity's `type`, `focus`, `model` |
| Ukrainian on its own terms: no explanation through Russian or "Slavic" comparison; Ukrainian grammatical terms (звук / літера, відмінок, наголос) | — |
| The language rule of §6 (narration language, quoted-term spans) | the immersion rule itself (from learner state) |
| The draft schema, the block kinds, the gloss and quoted-term markup, the gap procedure, the "may not" list below | — |

**Exemplars.** The card may carry exemplars of **voice and shape** under three conditions (operator decision 3): each is real, attested corpus text quoted with its source (R-35); each is from a domain no lesson of the band touches; a gate fails a draft that reuses an exemplar's **sentences** (r3: sentence-level reuse, not individual content words — a ban on shared content words would reject ordinary vocabulary). **Where the conversational models actually come from (r3):** the card alone cannot teach a writer to write a natural greeting or café exchange inside a 60-lemma allowlist, because the eligible exemplars are by construction from other domains. The attested conversational models for *this* lesson's situation come through the **evidence pack**: the pack builder (#8413 A2) admits, per dialogue situation the plan names, `EX-` records that are real exchanges from the corpus (ULP lesson notes are the first source — the Codex seat quoted sections 6277 and 6287 as examples of economical A1 exchanges), cited by the plan's `dialogue.evidence` and received by the writer as records. The card carries the general rules; the pack carries the situation's attested models. That keeps the four inputs.

## 6. What the writer may not do, and the language rule
Change the inventory; add, drop, merge or reorder a step or an activity; raise the English share; analyse a construction the arc marks as a chunk; type a stress mark, a gloss, a source line or a table of forms; use a lemma outside the allowlist; invent an example where the plan cites one, an error for an error-correction item, a video, a fact about Ukraine without a cited record; put a language or culture claim in a `tip`, `summary`, `callout` or `lead_in` (those are connective; a claim needs a block with `explains`); write about its own process or assess its own work; address the reviewer.
**The language rule (r3 — replaces "one sentence, one language").** Narration is in the language the immersion rule gives for the position; English narration may embed Ukrainian **quoted terms** (the ULP practice 1, `ulp-presentation-pattern.md:29`: Ukrainian first, gloss after), marked as a span (`{{uk:…}}` — exact syntax fixed by the schema) so that the immersion gate counts them as Ukrainian and the resolver resolves them; a Ukrainian sentence never embeds English except a gloss reference (§1d). Mixed sentences outside those two spans fail.

## 7. After the draft — the verification pass (R-26), in order (r3: every cheap check before anything paid; each check labelled by what it proves)
| # | Check | Proves | Failure goes to |
| --- | --- | --- | --- |
| 0 | **before the call:** evidence preflight (§4), cited forms' stress not `pending`, rendered-prompt check (§8) | availability | pack builder, word store or prompt — no call is made |
| 1 | schema: `lesson-draft-v1` with the per-type item schemas by `$ref`, echoed hashes equal the inputs, no accent characters, no unknown block kind, gap invariants (§4) | shape | writer |
| 2 | status: `evidence_gap` → stop | declared gaps | pack builder or plan |
| 3 | structure (§2) and evidence-use set arithmetic (§1a) | shape | writer |
| 4 | activities, deterministic part: the key index exists and is in range; multi-select sets are subsets of the options; every error item's `error_ref` resolves and its `incorrect` is in `sentence`, its `correct` is the correction | shape | writer |
| 5 | **assembly to the expanded document** (engine prints refs, glosses, paradigms, cards, resources) — from here on every check reads the expanded learner-facing text, not the writer's strings | — | engine |
| 6 | word target and immersion for the position — **measured on the expanded document by one counting contract** (below) | counts | writer |
| 7 | **words, deterministic part:** every token classified (§3) and narrowed to allowlist candidates; every `core` item and `recycled` id appears; each taught `forms` entry appears in a teaching position; used forms' stress not `pending`; tokens with no allowlist candidate fail | allowlist | writer; a word or form the lesson needs → **plan**; a form without a record → word store |
| 8 | **constrained questions** for the remaining ambiguities (§3 ii and iii), batched, answered by a language-lane seat, stored as resolution receipts — **a model's judgement, recorded, not a proof** | resolution | writer, if the answers show the text needs a sense outside the allowlist |
| 9 | stress applied from the records; Словник and Ресурси generated; the lesson locks and frontmatter written (#8413 Brief C) | — | engine |
| 10 | spelling and agreement by script — **proposed, not existing**: no grammar checker exists in the repository; an implementing brief settles whether to add one (LanguageTool was suggested) and what it may fail on; findings are evidence for a gate, never a verdict on Ukrainian (R-35) | signal | writer, or reported only |
| 11 | render: the four tabs build (`verify_shippable --astro-build`) | render | engine |
| 12 | review — the LLM gate of #8430 — **a model's judgement with receipts** | judgement | assigned by the driver |

**The immersion payload and counting contract (r3).** `compute_lesson_immersion_band` (#8414) is not implemented today; `compute_immersion_band` is module-indexed and the repository counts immersion two different ways (a character ratio in the audit cleaner, a token ratio in the linear pipeline). This contract fixes **one** contract for the fresh build, with R-30's numbers unchanged: the writer receives an **immersion payload** — for each field role (narration, dialogue line, activity instruction, activity item, gloss, quote, resource line) the permitted language(s), plus the structural targets of the band (`min_uk_dialogue_lines`, `min_uk_example_sentences`, `min_vocab_entries`) and the advisory share; the gate counts the advisory share as **Ukrainian tokens over all tokens of the expanded Урок tab**, with quoted terms counted as Ukrainian, glosses and `translation_en` counted as English, and Словник/Ресурси excluded; structural minimums are summed over the module's lessons until lesson-level minimums are calibrated (#8414). One function computes it, both the writer's payload and the gate read it.

**Regeneration.** The writer gets back a machine-readable failure — check, step or activity id, the token or item, the reason — never a log. **The same check failing twice on the same lesson is not retried**: the second failure goes to the plan or the pack. At most two regenerations of one lesson in all (operator decision 4), counted against the stable lesson identity (module slug, `n`) across every change of plan, pack, card or prompt — an upstream fix does not reset the count; then the driver. A regeneration invalidates that lesson's resolution receipts; the receipts of other lessons stand.

## 8. Before any paid run
1. **Rendered-prompt check (deterministic):** the prompt for a lesson contains no unresolved placeholder, no path or text of an earlier edition or of a v1 plan, no record the plan entry does not cite, nothing from another lesson (except the recap's built lessons), the per-type item shapes rendered from the level schema, and the card hash it names exists.
2. **Dry inventory:** the homograph list and the `pending` check run before the call.
3. **Semantic canary, and what it cannot certify (r3):** position 1, lesson 1 is written once, passes checks 0–11 and is reviewed under #8430 before any second lesson is written. It succeeds when it passes with at most one regeneration; it stops the pilot when the same check fails twice, and the failure is fixed at its layer first. A literacy lesson exercises neither error correction, nor paradigms, nor hard homographs, nor recap inputs, nor later immersion bands; those paths are certified by **contract fixtures** (synthetic drafts through checks 1–9 for each: a same-stress sense ambiguity, a marked form, a hyphenated compound, an intentional error item, a regeneration that invalidates receipts) run in CI before the pilot, and by the held-out evaluation of #8430 as later lessons are built.

## Decisions of the operator, 2026-09-21 (unchanged in r3)
Question 1 he answered himself; on the others he said **"i accept the defaults"**, so each proposal is a decision.
1. **Any form of an allowed lemma may be used; an untaught form is memorised, not explained** (§3; plan schema revision 8).
2. **The writer types no stress marks; the engine applies them and never guesses.** An ambiguous token gets one constrained question, answered by a language-lane seat and checked in review. The pilot measures how many tokens need it.
2a. **Словник and Ресурси are generated, not written** — with the sense the lesson uses, the government of a verb or preposition where the word record carries it, grouping by the plan's steps, and the plan's `use:` line in Ресурси. All from sourced fields.
3. **One style card per band — A1, A2, B1+.** Exemplars only under the three conditions of §5.
4. **Two regenerations of a lesson, then the driver;** the same check failing twice is not retried but goes to the plan or the pack.
