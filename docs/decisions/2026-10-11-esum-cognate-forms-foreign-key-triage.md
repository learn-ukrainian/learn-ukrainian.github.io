## 1. Outcome & Executive Summary

This decision record provides the authoritative triage and durable remediation roadmap for the **134,836 foreign-key violations** in `data/sources.db` between `esum_cognate_forms.entry_id` and `esum_etymology_meta.id`.

### Key Findings
1. **Root Cause:** A complete ID-space displacement occurred between `esum_cognate_forms` (`entry_id` range `62,945..215,657`, total 134,836 rows) and `esum_etymology_meta` (`id` range `215,658..251,834`, total 36,177 rows). The cognate forms table was generated by `scripts/etymology/extract_cognate_forms.py` against a pre-ULIF/pre-deduplication version of `esum_etymology_meta` and was not re-keyed when `esum_etymology_meta` was rebuilt with 36,177 canonical entries.
2. **Semantic Safety:** Sources MCP tools (`search_esum` and `search_esum_batch` in `scripts/wiki/sources_db.py`) query **only** `esum_etymology_meta` (exact lemma matches) and `esum_etymology` (FTS5 full text search). Neither tool references or joins `esum_cognate_forms`. All dictionary and etymology lookups across curriculum and agent pipelines are **100% functional and semantically unaffected**.
3. **Contract Protection:** Live host mutations are strictly prohibited. Existing Phase 3 recovery and freeze gates (`phase3_recovery_contracts.py`, `phase3_live_ingest_gate.py`, and `phase3_university_content_audit_freeze.py`) explicitly pin and verify `foreign_key_failure_count == 134836` with cryptographic hash `9938f7cbab6cca94bfd0a360eec114fdef404a357e02b24161da0f7cf5c6d9bb`.
4. **Remediation Plan:** Durable re-keying and cleanup is scheduled for the next major database cutover (Sources DB v5/v6 re-ingest), allowing atomic updates to the database tables and Phase 3 verification contracts.

## 2. Root Cause Analysis

### Database Schema Definition
In `data/sources.db`:
```sql
CREATE TABLE esum_cognate_forms (
    entry_id INTEGER PRIMARY KEY,
    cognate_forms TEXT NOT NULL DEFAULT '{}',
    proto_form TEXT,
    extracted_count INTEGER NOT NULL DEFAULT 0,
    expected_count INTEGER NOT NULL DEFAULT 0,
    cognate_forms_recovered TEXT NOT NULL DEFAULT '{}',
    FOREIGN KEY(entry_id) REFERENCES esum_etymology_meta(id)
);

CREATE TABLE esum_etymology_meta (
    id INTEGER PRIMARY KEY,
    lemma TEXT NOT NULL,
    vol INTEGER NOT NULL,
    page INTEGER NOT NULL,
    entry_hash TEXT NOT NULL DEFAULT '',
    etymology_text TEXT NOT NULL,
    cognates TEXT NOT NULL DEFAULT '[]',
    source TEXT NOT NULL DEFAULT 'ЕСУМ',
    UNIQUE(lemma, vol, page, entry_hash)
);
```

### ID Space Divergence
Authoritative query against `data/sources.db`:
```sql
SELECT 'esum_etymology_meta', COUNT(*), MIN(id), MAX(id) FROM esum_etymology_meta
UNION ALL
SELECT 'esum_cognate_forms', COUNT(*), MIN(entry_id), MAX(entry_id) FROM esum_cognate_forms;
```
Result:
| Table | Row Count | Min ID | Max ID |
|---|---:|---:|---:|
| `esum_etymology_meta` | 36,177 | 215,658 | 251,834 |
| `esum_cognate_forms` | 134,836 | 62,945 | 215,657 |

Notice:
- `max(entry_id)` in `esum_cognate_forms` is `215,657`.
- `min(id)` in `esum_etymology_meta` is `215,658` (`215,657 + 1`).
- The two ID spaces are **strictly disjoint**. Every single row in `esum_cognate_forms` references an ID strictly lower than any existing ID in `esum_etymology_meta`.
- Consequently, `PRAGMA foreign_key_check(esum_cognate_forms)` returns exactly **134,836** rows (100% of the table).

### Historical Context
- On 2026-06-14 (per `docs/decisions/2026-06-14-etymology-feature-design.md`), `scripts/etymology/extract_cognate_forms.py` was introduced to regex-extract cognate forms from etymology texts.
- At that time, `esum_etymology_meta` contained 134,836 rows in ID space `62,945..215,657`.
- During subsequent database normalization and ULIF migration, `esum_etymology_meta` was consolidated with unique constraints into 36,177 canonical entries and re-indexed into ID space `215,658..251,834`.
- Because SQLite connections run by default without `PRAGMA foreign_keys = ON`, the foreign key was not evaluated at insert time, preserving the table without error while creating the 134,836 foreign key violations.

## 3. Query Impact & Semantic Audit

### MCP Tools: `search_esum` and `search_esum_batch`
Inspection of `scripts/wiki/sources_db.py`:
- `search_esum_batch()` (lines 3499–3559): Queries `esum_etymology_meta` directly for exact lemma matches (`meta.lemma = requested.word COLLATE NOCASE`).
- `search_esum()` (lines 3780–3880): Queries `esum_etymology_meta` for candidate lemma matches and `esum_etymology` (FTS5 table) for full-text matches.
- **Neither function joins or queries `esum_cognate_forms`.**
- Verification: Runtime invocation of `search_esum('серце')` and `search_esum_batch(['дім', 'мова'])` executes cleanly without error and returns full etymology entries with reconstructed forms, volume, and page citations.

### Downstream Code References
- `scripts/etymology/build_data_manifest.py:100`:
  ```sql
  SELECT e.id, e.lemma, e.vol, e.page, e.etymology_text,
         COALESCE(f.cognate_forms, '{}') AS cognate_forms,
  ```

## 4. Frozen Contracts & Non-Goals

### Non-Goal: No Live Host Database Mutation
Ad-hoc deletion or re-keying of `esum_cognate_forms` in `data/sources.db` is **strictly prohibited**.

## 5. Durable Remediation Roadmap (Database Cutover v5/v6)

When the next scheduled major database cutover takes place:

1. **Option A (Regenerate from Current Meta — Recommended):**
   Re-run `scripts/etymology/extract_cognate_forms.py` against the 36,177 canonical entries in `esum_etymology_meta`.
   - Result: 36,177 rows in `esum_cognate_forms` matching `entry_id = esum_etymology_meta.id`.
   - Foreign-key check violations drop to 0.
   - `build_data_manifest.py` `LEFT JOIN` resolves populated cognate forms.

2. **Option B (Preserve Fine-Grained Forms in Archive):**
   If the 134,836 historical forms contain sub-lemma extractions not captured in the 36,177 top-level entries, move them to `esum_cognate_forms_archive` (without foreign key constraints) and generate clean 1:1 forms for the active table.

3. **Contract Update:**
   Atomically update `EXPECTED_DATABASE["foreign_key_failure_count"] = 0` and update `phase3_live_ingest_gate.py` and `phase3_recovery_contracts.py` as part of the database cutover release PR.
