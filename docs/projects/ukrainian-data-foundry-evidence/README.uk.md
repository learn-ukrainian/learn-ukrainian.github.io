# Українська фабрика даних: сигнали на рівні документа v0

Сигнали на рівні документа v0 — це детерміністичний шар доказових даних
для повного реєстру зовнішніх і загальнодоступних текстів, написаних людьми.
Він допомагає команді дослідити походження, готовність правових відомостей,
склад корпусу, можливі дублікати, нормалізацію, поєднання абеток, повторювані
технічні фрагменти та перетин з відкладеними оцінювальними вибірками до
створення будь-якої навчальної вибірки.

Цей інструмент не визначає, чи написано речення доброю українською мовою. Він
не допускає записи до навчання, не виправляє й не вилучає їх, не поширює
вихідні тексти, не оприлюднює набір даних і не навчає модель.

Це сигнали для подальшого дослідження, а не мовні висновки. Російські літери
можуть бути в цитаті, бібліографічній назві, мовленні персонажа чи історичному

про період, жанр, регістр і походження.

Перевірка перетину охоплює лише текстові алгоритми, зазначені у квитанції. Вона
не доводить відсутності перекладеного, перефразованого або семантично
еквівалентного витоку оцінювальних даних.

## Що містить один рядок

Кожен рядок JSONL містить лише доказові відомості та непрозорі ідентифікатори:

- сталі `record_id`, `source_id` і `work_id`;
- точний `content_sha256` вихідних байтів;
- групу джерел та ідентифікатор ресурсу в реєстрі;
- період, жанр, регістр і походження;
- стан доказів щодо походження, отримання, знімка даних, прав, людського походження та
  забруднення;
- окремі стани для поширення вихідного тексту, локального навчання моделі,
  навчання моделі й оприлюднення набору даних;
- детерміністичні показники довжини, абеток, нормалізації та повторюваного тексту;
- групу й кількість точних дублікатів;
- вісім смуг цифрового відбитка для пошуку можливих наближених дублікатів; і
- стан перетину з відкладеними оцінювальними даними та назву методу.

Кожна подальша можливість використання має стан
`not_decided_by_document_signal_manifest`. Допуск української Вікіпедії на
рівні групи збережено, але він не перетворюється автоматично на дозвіл поширити
текст, навчити модель або оприлюднити набір даних. Таке рішення ухвалює окрема
перевірка прав для конкретного способу використання.

## Побудова й перевірка

Команди треба виконувати в копії репозиторію, де наявна локальна база
`data/sources.db`:

```bash
mkdir -p batch_state/document-signals

.venv/bin/python scripts/projects/open_model_data/document_signal_manifest.py \
  --config data/projects/open_model_data/evidence/document_signal_config_v1.json \
  --input-root . \
  --manifest-output batch_state/document-signals/document_signal_manifest_v1.jsonl \
  --receipt-output batch_state/document-signals/document_signal_receipt_v1.json
```

Перевірити вже створену пару файлів можна без читання бази джерел:

```bash
.venv/bin/python scripts/projects/open_model_data/document_signal_manifest.py \
  --verify-existing \
  --manifest-output batch_state/document-signals/document_signal_manifest_v1.jsonl \
  --receipt-output batch_state/document-signals/document_signal_receipt_v1.json
```

База SQLite відкривається у режимі лише для читання. Для підрахунку точних
дублікатів використовується обмежений проміжний файл SQLite. Маніфест
записується потоком у тимчасовий файл. Пара маніфесту й квитанції стає чинною
лише після повного покриття та перевірки відповідності схемам із жорсткими
обмеженнями. Неповне джерело або помилковий рядок не залишає успішно
перевіреної пари результатів.

## Як це має використовувати команда розробників моделі

1. Відтворити маніфест і перевірити хеші та повноту реєстру.
2. Назвати конкретний спосіб використання: локальне дослідження, локальне
   навчання моделі, навчання на зовнішній інфраструктурі, поширення вихідного
   тексту або оприлюднення
   набору даних. Окремо перевірити правові підстави саме для цього способу.
3. Явно вибрати групи джерел і мовні зрізи. Повідомляти баланс періодів,
   жанрів, регістрів і походження. Зазначити цей баланс, а не називати всі рядки просто «українськими
   даними».
4. Об'єднати точні дублікати за ідентифікатором групи. Спільні смуги
   наближеного відбитка використовувати лише для створення черги кандидатів,
   після чого перевіряти попарну подібність і контекст.
5. Дослідити кандидатів із відхиленнями нормалізації, поєднанням абеток,
   керівними символами, символами заміни й повтореними рядками. Не стирати
   цитати, художній текст, історичну мову, діалекти, успадковані форми та
   маркований регістр.
6. Після кожного перетворення повторно перевіряти перетин з оцінювальними
   даними: похідний текст може створити витік, якого не було у вихідному записі.
7. Створити навчальну вибірку лише через перевірку Фабрики даних для
   конкретного способу використання. Нова квитанція має пов'язувати точні
   джерельні записи, перетворення, вилучення, правові зобов'язання та хеш
   результату.

## Обмеження

- Кількість літер і поєднання абеток не визначають мову тексту.
- Наявність слова у ВЕСУМ або словнику не доводить правильності в контексті.
- Смуги наближеного відбитка створюють кандидатів, але не встановлюють
  дублювання.
- Сигнали повторюваного тексту не відрізняють технічний шаблон від
  літературного повтору.
- Текстова перевірка витоку не виявляє семантичних або перекладених збігів.
- Жодне рішення про допуск групи та жоден технічний сигнал автоматично не створюють навчальний
  запис.
- Для цього шару не запускали модель або класифікатор, не орендували
  прискорювач, не використовували платні обчислення, нічого не завантажували й
  не зверталися до зовнішніх команд.

Наступний етап програми — рішення щодо прав для кожного способу використання та
перше стратифіковане доповнення до корпусу для продовження попереднього навчання.
Окрема лінія контекстних виправлень і захисту мовної варіативності потребує
авторитетних словникових джерел і перевірки моделями, що добре опрацьовують
українську мову.
