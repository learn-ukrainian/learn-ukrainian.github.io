# Етап 2: доповнення з урахуванням правових обмежень

[Англійська версія](PHASE2_COMPLEMENTS.md)

Етап 2 — це локальний детерміністичний крок маршрутизації доказових даних. Він
приймає перевірений маніфест JSONL Етапу 1 `document_signal_record_v1` та його
квитанцію, а тоді створює три артефакти без текстових даних:

- доповнення JSONL `prepared_data_complement_record_v1` з одним записом на
  кожен запис маніфесту;
- робочий перелік JSONL `evidence_resolution_item_v1` з окремим елементом для
  кожного фактичного ідентифікатора джерела та кожної нерозв'язаної,
  заблокованої або виключеної можливості; і
- квитанцію `prepared_data_complement_receipt_v1`, яку записують останньою як
  маркер фіксації комплекту.

Спочатку відтворіть Етап 1 локально. Маніфест навмисно не зберігається в
репозиторії; вхідними даними, зафіксованими в репозиторії, є
`document_signal_config_v1.json` і `document_signal_receipt_v1.json`.

```bash
.venv/bin/python -m scripts.projects.open_model_data.document_signal_manifest \
  --config data/projects/open_model_data/evidence/document_signal_config_v1.json \
  --input-root . --manifest-output /safe/local/phase1-manifest.jsonl \
  --receipt-output /safe/local/phase1-receipt.json --spool /safe/local/phase1-spool.sqlite
```

Перед запуском Етапу 2 створіть зафіксований у репозиторії супровідний файл
локаторів, безпечний для оприлюднення:

```bash
.venv/bin/python -m scripts.projects.open_model_data.source_work_locator_index \
  --config data/projects/open_model_data/evidence/source_work_locator_config_v1.json \
  --input-root . \
  --output data/projects/open_model_data/evidence/source_work_locator_index_v1.jsonl
```

Файл локаторів містить лише дозволені списком допуску метадані джерел і
матеріалів, канонічний локатор, якщо він справді відомий, непрозорі
ідентифікатори, сумісні з Етапом 1, та кількісні показники. Він ніколи не
містить фрагментів, джерельного тексту, цифрових відбитків оцінювальних даних
або твердження про наявність дозволу. Споживач може перевірити зафіксований у
репозиторії файл локаторів, не маючи нашого корпусу; для його повторної побудови
потрібні відповідні локальні бази джерел.

Після цього запустіть Етап 2 із результатами Етапу 1 та файлом локаторів:

```bash
.venv/bin/python -m scripts.projects.open_model_data.source_capability_complements build \
  --phase1-manifest /safe/local/phase1-manifest.jsonl \
  --phase1-receipt /safe/local/phase1-receipt.json \
  --policy data/projects/open_model_data/evidence/source_capability_policy_v1.json \
  --locator-index data/projects/open_model_data/evidence/source_work_locator_index_v1.jsonl \
  --complement-output /safe/local/complement.jsonl \
  --worklist-output /safe/local/evidence-worklist.jsonl \
  --receipt-output /safe/local/complement-receipt.json
```

Споживач може самостійно отримати матеріал, на використання якого має право, а
тоді зіставити записи за канонічним локатором, метаданими матеріалу й
`content_sha256` із доповнення. Супровідний файл не надає байтів джерела й не
дає дозволу на навчання моделі, повторне поширення, завантаження чи
оприлюднення.

Перед використанням артефакту перевірте всі зв'язки вхідних даних і кожен байт
кожного результату:

```bash
.venv/bin/python -m scripts.projects.open_model_data.source_capability_complements verify \
  --policy data/projects/open_model_data/evidence/source_capability_policy_v1.json \
  --locator-index data/projects/open_model_data/evidence/source_work_locator_index_v1.jsonl \
  --phase1-manifest /safe/local/phase1-manifest.jsonl \
  --phase1-receipt /safe/local/phase1-receipt.json \
  --complement /safe/local/complement.jsonl \
  --worklist /safe/local/evidence-worklist.jsonl \
  --receipt /safe/local/complement-receipt.json
```

`filter` не читає джерельних даних: він читає лише доповнення без текстових
даних і вимагає вказати одну відому незалежну можливість, стан і, за потреби,
маршрут.

```bash
.venv/bin/python -m scripts.projects.open_model_data.source_capability_complements filter \
  --complement /safe/local/complement.jsonl \
  --capability local_model_learning --state evidenced --route candidate --faithful
```

## Чинний стан політики й обмеження

Контекст політики стосується стороннього споживача загальнодоступних результатів,
який працює локально. Це запис доказових даних, а не юридична консультація; він
не визначає, право якої юрисдикції застосовується. Можливості навмисно незалежні:
для отримання й зберігання, локальної підготовки, локального навчання моделі,
поширення вихідних даних, поширення похідних даних, оприлюднення набору даних
та оприлюднення моделі окремо зберігаються власні стан і маршрут. Перетин за
всіма можливостями не застосовується.

Наявні прийняті докази щодо прав і допуску Вікіпедії дають доказові підстави для
локального зберігання, підготовки й локального навчання моделі в межах
задекларованої сфери локального використання загальнодоступним споживачем. Вони
не розв'язують питань поширення вихідних або похідних даних, оприлюднення набору
даних чи оприлюднення моделі. Значення за замовчуванням для інших груп джерел
залишаються нерозв'язаними, якщо не додано окремого перевизначення для джерела з
доказами, які дають змогу ухвалити рішення. Часткові докази зберігаються з
конкретно вказаними відсутніми ключами, а не відкидаються.

Доповнення точно пов'язує кожне поле Етапу 1 без текстових даних, зокрема
виміри, стан доказів, хеш вмісту, сигнали, сигнали дублікатів і сигнал
забруднення відкладених даних. Ці діагностичні відомості ніколи не вилучають
записів. Точне подання стає кандидатом лише тоді, коли підтверджено доказами і
локальну підготовку, і локальне навчання моделі. Подання з маскуванням втрат і
захищені подання залишаються `not_classified_phase2`, доки немає доказів на
рівні рядків.

Для побудови потрібен рівно один рядок локатора, що відповідає схемі, для
кожної фактичної пари `source_id`/`work_id` з Етапу 1. Вона відхиляє відсутні,
зайві, переставлені або дубльовані зіставлення локаторів, а також зіставлення з
невідповідною групою джерел, невідповідним реєстром чи зміненим хешем. Кожен
рядок доповнення пов'язує свій запис локатора та хеш індексу; кожен елемент
робочого переліку містить придатні посилання на локатори всіх матеріалів, яких
він стосується; а квитанція пов'язує і артефакт локаторів, і схему. Наявність
локатора — це лише метадані для зіставлення: вона ніколи не надає прав на
навчання моделі, повторне поширення, завантаження чи оприлюднення.

Під час побудови дані Етапу 1 і створювані файли JSONL опрацьовуються потоком.
Вони зберігають лише один поточний рядок, повне відображення локаторів без
текстових даних, зведені лічильники, кількість пар джерело/матеріал і потрібні
для побудови робочого переліку посилання на локатори для кожного джерела.
Вихідний текст або всі рядки Етапу 1 вони не зберігають.

## Квитанція виробничого запуску

Повна побудова від 2026-08-03 узгодила всі 189,150 записів Етапу 1 і 42,302
локатори пар джерело/матеріал. Індекс локаторів охоплює 3,309 літературних,
36,759 підручникових, 1,205 зовнішніх статей і 1,029 зіставлень Вікіпедії.
Робочий перелік доказів щодо можливостей містить 3,511 завдань на рівні джерел.

За наявними доказами 1,029 рядків Вікіпедії спрямовуються до маршруту
`candidate` з точним поданням для локальної підготовки й локального навчання
моделі. Інші 188,121 запис спрямовуються до `metadata_only` для цих можливостей;
це означає, що питання доказів і далі не розв'язано, а не те, що записи мають
мовні вади або назавжди непридатні до використання. Усі 189,150 рядків
залишаються `metadata_only` для поширення вихідних або похідних даних,
оприлюднення набору даних та оприлюднення моделі. Етап 2 не виконує мовної
класифікації з маскуванням втрат або захистом.

Дві повні побудови дали побайтово однакові результати. Незалежний засіб
перевірки повторно побудував комплект і підтвердив збіг кожного байта. Фільтр
усього корпусу, який не читав джерельних даних, повернув ті самі 1,029
підтверджених доказами кандидатів із точним поданням. Зафіксована в репозиторії
квитанція пов'язує локальне доповнення розміром 958,068,153 байти й робочий
перелік розміром 67,845,464 байти; ці два матеріальні артефакти залишаються
локальними й не є матеріалами для оприлюднення.

Засіб побудови використовує атомарні тимчасові файли, а не проміжний файл

джерел, потрібних для відтворення Етапу 1 та індексу локаторів.

Поле квитанції `coverage.by_period` зберігає задекларований на Етапі 1 вимір
історичного періоду; це не мовний висновок. `coverage.by_textbook_grade`
повідомляє точний розподіл за класами, а `route_totals` і
`representation_totals` дають змогу перевірити рішення щодо можливостей і
подань без читання тексту.

Цей процес не створює готового до використання корпусу й не запускає модель.
Наступна контрольна перевірка розв'язання питань щодо прав — пакет Вікіджерел із
52 рядків, по одному для кожної сторінки; після неї буде розв'язано питання про
твір і видання для практично корисних літературних шарів. Наступний мовний етап
є окремим: це авторитетні докази для контекстного виправлення українського
тексту й захисту мовної варіативності, а не автоматична нормалізація
історичного, діалектного, регіонального, цитованого матеріалу або матеріалу з
мовним контактом.
