# Етап 3: доказові контракти виправлення та захисту

[English version](PHASE3_CONTRACTS.md)

Етап 3 додає модельно-нейтральний доказовий продукт для виправлення
української мови та запобігання стиранню нормативних і маркованих різновидів.
Він не створює людського золотого стандарту й не змінює наявний контур
виправлень, який вимагає рішень кваліфікованих рецензентів.

Кожен випадок Етапу 3 має один кінцевий статус:

- `correct` — прийнятний контрольний приклад, який треба залишити без змін;
- `correction` — неавторитетна пропозиція, що пройшла зафіксований поріг своєї
  категорії;
- `protected` — контекст, який не можна нормалізувати за оприлюдненим правилом;
- `excluded` — матеріал поза навчальним або виправним представленням;
- `unresolved` — правомірне кінцеве утримання від рішення.

Ці назви не визначають рівня надійності. Кожен запис і кожне споживче
представлення мають обов'язкові константи схеми
`assurance_tier: evidence_graded_non_gold` та `authoritative: false`.
Ідентифікатори випадків мають окремий простір `cp_case:` і не можуть бути
сприйняті як людсько верифіковані записи `correction_record_v1`.

## Межі доказів і джерел

Канали доказів не змішуються. VESUM підтверджує лише морфологічну наявність або
відсутність; R2U та російський морфологічний аналіз дають докази російської
форми; УМІФ, названі історичні словники, LanguageTool, `nlp_uk`, корпусний
контекст і модельні пропозиції зберігають власні ідентичності, версії,
локатори, квитанції парсерів та обмеження. Один голос моделі або відсутність у
VESUM не можуть створити статус `correction`.

Початковий текст є незмінним. Оприлюднений запис містить текст джерела лише
тоді, коли для конкретного джерела доведено саме можливість такого
оприлюднення. В інших випадках випуск містить лише окрему анотацію: локатор із
зафіксованою редакцією, зміщення, хеші, ідентичність джерела й твору, докази та
код відтворення. Створені проєктом контрольні приклади явно позначають своє
походження.

Етап 2 залишається джерелом істини щодо можливостей використання. Чинна
публічна політика дозволяє локальне опрацювання й локальне навчання для 1 029
записів Вікіпедії, однак усі 189 150 записів мають лише метадані щодо
повторного поширення сирих і похідних даних, оприлюднення набору даних та
моделі. Етап 3 не виводить право на оприлюднення з доказів локального навчання.

## Зафіксована вибірка слів поза VESUM

Перший виробничий доказ — детерміністична вибірка з точних 9 292 022
слововживань, не знайдених у VESUM і зафіксованих повним профілем корпусу.
Добір:

1. потоково читає чотири допустимі групи джерел із SQLite лише для читання;
2. відтворює нормалізацію профілю та інтерфейс VESUM;
3. розподіляє сталу квоту кожної групи між періодом, жанром і регістром за
   детерміністичним методом найбільших остач;
4. ранжує слововживання за доменно відокремленим SHA-256;
5. записує безтекстові результати у сталому порядку.

Кожне вибране слововживання належить до одного доказового класу:
`ocr_or_noise`, `proper_name`, `historical_orthography`,
`foreign_or_russian_quotation`, `phonetic_russian`,
`plausible_modern_ukrainian_error`, `legitimate_ukrainian_variation` або
`unresolved`. Це маршрути доказового аналізу, а не автоматичні назви помилок.
Сукупну кількість невідомих слів ніколи не використовують як мовний висновок.

Зафіксована конфігурація визначає розмір вибірки, квоти груп, осі, алгоритм
ідентичності, вхідні версії, заборону тексту та межу закритого сховища.
Квитанція пов'язує точний знаменник, хеші входів, розподіл категорій,
покриття, байти й хеш результату та тотожність двох запусків.

## Відмінність від наявних інструментів

Маніфест екосистеми фіксує перевірені версії українського модуля LanguageTool,
`nlp_uk` і VESUM, а також окремі обмежені спостереження вебінтерфейсів R2U та
УМІФ. Етап 3 доповнює ці засоби, але не проголошує себе їхньою заміною і не
стверджує, що перевірив усі їхні можливості.

Вимірювана відмінність — окреме походження доказів для кожного випадку та
політично визначені результати `protected` і `unresolved`. Відповідь
інструмента лишається діагностичним доказом: збіг, відсутність збігу, наявність
чи відсутність у словнику самі собою не доводять правильності або хибності
української форми.

## Зафіксовані пороги категорій

Конфігурацію порогів додають до репозиторію до запуску фабрики випадків.
Кожна категорія визначає споживче рішення, мінімум підтверджених джерелами
випадків і контрольних прикладів, вимоги захисту, дозволені статуси та умови
зупинки. Категорія, що не пройшла поріг, отримує стан `research_only`: вона й
далі присутня у звіті про покриття та перевірці нестиральності, але не може
випускати виправлення.

Обов'язкова незалежна від джерела перевірка містить три створені проєктом
речення:

1. `Фраза звучит значно вишуканіше.` в авторському викладі треба позначити як
   російську особову форму дієслова;
2. ту саму форму в маркованій російській цитаті треба захистити;
3. сучасний український контроль, підтверджений VESUM, треба залишити без змін.

Етап 3 додає мутації меж цитати. Публічні приклади є регресійними перевірками,
а не захищеною від витоку контрольною вибіркою. Дані про закритий добір
зберігаються лише у визначеному ігнорованому приватному сховищі поза публічним
репозиторієм.

## Межа відтворення

Для відтворення потрібні зафіксоване середовище Python репозиторію, локальний
маніфест Етапу 1 у `batch_state/issue-6327/phase1-production/`,
`data/sources.db` і `data/vesum.db`. Виробнича команда:

```bash
.venv/bin/python scripts/projects/open_model_data/vesum_unattested_sample.py build \
  --config data/projects/open_model_data/profiles/vesum_unattested_sample_config_v1.json \
  --profile data/projects/open_model_data/profiles/public_external_full_corpus_v1.json \
  --profile-receipt data/projects/open_model_data/profiles/full_corpus_profile_v1.json \
  --phase1-manifest batch_state/issue-6327/phase1-production/document_signal_manifest.jsonl \
  --phase1-receipt batch_state/issue-6327/phase1-production/document_signal_receipt.json \
  --source-database data/sources.db --vesum-database data/vesum.db \
  --detector-config data/projects/open_model_data/detector/language_contact_config_v1.json \
  --output data/projects/open_model_data/profiles/vesum_unattested_sample_v1.jsonl \
  --receipt data/projects/open_model_data/profiles/vesum_unattested_sample_receipt_v1.json
```

Виробничу побудову двічі незалежно виконано з баз даних. Результат і квитанція
в обох запусках побітово однакові. Перевірений результат містить 256 записів —
по 64 для `external_articles`, `literary`, `public_textbooks` і `wikipedia`:

- SHA-256 результату:
  `a8d2ed4f8ef2170e27bd52cc4e9d475efa5261fec7e6f822703bf9340630b414`;
- SHA-256 квитанції:
  `88741e1a6f104ac491b3ee1142b25e88a82fff3350b09d6d8d3bbd6a9c2f13f2`;
- маршрути: 200 `unresolved`, 26 `foreign_or_russian_quotation`, 20
  `legitimate_ukrainian_variation`, чотири `historical_orthography`, чотири
  `plausible_modern_ukrainian_error`, один `ocr_or_noise` та один
  `proper_name`.

Обидві бази відкривають лише для читання. Навчання, завантаження моделі,
обчислення на прискорювачі, вивантаження або зовнішнє оприлюднення даних не
виконуються.
