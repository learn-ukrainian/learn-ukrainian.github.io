### r1
## Design note — the remaining #7139 item: empty-host alarm ("near-zero burn while paid seats are underused") — for cross-family critique

**Facts (tool-read through the tunnel, 2026-08-24 19:18Z).** `/api/occupancy` already exposes per host `idle_or_empty` + `burn_state` + `observed_at` (`host-job` is `idle_or_empty: true` right now). The API host runs a CodexBar scheduler (`/api/health.codexbar`: 6 providers, refresh 720 s) but `/api/state/routing-budget` returns `records_loaded=0`: every lane's `burn_pct_7d` / `remaining_pct` / `codexbar.*_used_pct` is `null` and `status: unknown` — the services host has no subscription usage data (the CodexBar CLI with real data runs on the notebook; #M-14). So today an "underused paid seats" signal cannot be computed on the API host honestly, and the alarm must not be faked from `idle_or_empty` alone.

**Proposal.**
1. **Lane usage arrives from the notebook over the existing reporter.** The notebook project-state reporter (schema v2, #7188/#7187; LaunchAgent #7257) gains an optional `lane_usage` block: per lane `{lane, window: "5h"|"weekly", used_pct, resets_at}` read from the local CodexBar CLI (`codexbar usage --json --provider <lane>`), sanitized (no account emails/ids, no dollar figures, no plan names beyond the lane token); stored per reporting host with the same TTL/monotonic rules; missing block ⇒ `lane_usage_status: unreported`.
2. **Server-side alarm, honest by construction.** `GET /api/occupancy` gains `attention` items and `fleet.html` a banner: `empty_host_underused` fires for a host when (a) `idle_or_empty` has held for ≥ 15 min (occupancy already tracks `observed_at`; add a small in-process "idle since" memo), **and** (b) at least one lane's freshest reported `used_pct` is below pace, pace = elapsed fraction of its window (`(now − window_start)/window_len`), with a 10-point tolerance. If no fresh lane usage exists ⇒ `attention: empty_host_unknown_capacity` ("host idle; lane headroom unknown — reporter not installed") — never silence, never a fabricated "underused".
3. **Routing-budget stops answering `unknown` with nulls when data exists.** `/api/state/routing-budget` reads the reported lane usage as one more source (labelled `source: notebook-report`, with `age_s`), so the recommendation stops being suppressed for lack of records; it keeps `unknown` when nothing fresh was reported.
4. **Tests.** Reporter: lane_usage sanitizer (rejects emails, account ids, dollar strings, unknown lanes) and CLI-output fixture parsing; store: TTL/monotonic reuse; alarm matrix: idle<15 min → none; idle≥15 min + lane under pace → `empty_host_underused`; idle≥15 min + all lanes at/over pace → none; idle≥15 min + no usage → `empty_host_unknown_capacity`; page contract test for the banner; M5 sweep covers the new fields.

**Non-goals.** Spend in currency, per-account identity, auto-dispatch on alarm (the operator/orchestrator decides what to run), new probes from the API host.

**Open for critique.** (i) is the notebook reporter the right carrier for account-level usage (it is per host, usage is per subscription)? (ii) pace with a flat 10-point tolerance vs the existing `codexbar` pace notion in `scripts/config` (reuse if one exists); (iii) 15-minute idle threshold; (iv) whether the alarm belongs on `/api/occupancy` (host glance) or `/api/fleet/workers/v1` (attention list exists there already).

### r2 (binding)
## Design r2 — empty-host alarm (after Gemini-seat critique: PASS-WITH-CHANGES, 4 required changes folded). Design of record for implementation.

1. **Pace is evaluated on weekly/billing windows only.** Rolling 5-hour burst windows never feed `used_pct < pace` (a normal 15-minute pause would drop them below pace while the weekly quota is exhausted). Reuse the existing formula in `scripts/api/codexbar_usage.py` (`expected_pct = elapsed_fraction * 100`, `weekly_pace_delta_pct = weekly_used_pct − expected_pct`); "under pace" = `weekly_pace_delta_pct < −10`.
2. **Lane usage is estate-wide, not per host.** Only the notebook runs CodexBar; the alarm evaluator for any idle host reads the *freshest live* `lane_usage` across all stored reports (not the idle host's own report). Store keeps the per-report block; the evaluator selects by `collected_at`. Freshness bound: one cadence + grace, else `unknown`.
3. **Strict allowlist sanitizer on both ends.** The collector emits only `{lane, window: "weekly", used_pct, resets_at}` per lane from the CodexBar JSON (which carries `accountEmail`, `accountOrganization`, `loginMethod`, cost fields — all dropped at the source); the server's project-state sanitizer validates the block against the same allowlist and rejects any foreign field or non-lane token.
4. **Idle-since starts at process start.** The in-process idle memo initializes to `monotonic()` at boot, so no host can trip the 15-minute idle rule before 15 minutes of *observed* idleness; the memo resets whenever `idle_or_empty` turns false.
5. Unchanged from r1: alarm items `empty_host_underused` / `empty_host_unknown_capacity` on `/api/occupancy` (host glance) with a `fleet.html` banner; `routing-budget` consumes the reported weekly usage as `source: notebook-report` with `age_s` (the pinned suppression rule is unaffected: it lifts only when authoritative data exists); non-goals stand (no currency, no identity, no auto-dispatch).

Tests: collector allowlist (fixture CodexBar JSON with PII → only four fields survive; foreign field ⇒ rejected server-side); weekly-only pace (5h fixture ignored); estate-wide selection (idle `host-job` + notebook report ⇒ evaluated; no report ⇒ `unknown_capacity`); idle-since boot init (idle immediately after start ⇒ no alarm until 15 min of observation); alarm matrix; page contract; sweep coverage of the new fields.
