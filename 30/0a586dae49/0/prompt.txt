## Questions to answer (each with measurements)

1. **Wall-clock cost per hook event.** Time each hook script standalone (`time bash <hook> < /dev/null`
   with a representative env; note which env vars matter). Which hooks run on which events
   (SessionStart, PreToolUse, PostToolUse, Stop, SessionEnd, PostCompact)? What is the TOTAL added
   latency per user turn and per session start?
2. **Subprocess fan-out.** Count python/curl/git spawns per hook invocation (e.g. `bash -x` trace,
   count exec lines). session-setup.sh is suspected of spawning many short-lived .venv pythons —
   each ~100-300ms. Which could be merged into one python call?
3. **Context injection size.** Measure bytes/estimated tokens each SessionStart source injects:
   profile capsule, epic banner, rollover/handoff output, INFO lines, CLAUDE.md chain (user + project +
   rules files), MEMORY.md. What is duplicated (e.g. rules digest in CLAUDE.md vs served /api/rules vs
   .claude/rules/*)? What is stale?
4. **Failure-path quality.** The 2026-08-06 case study: `thread_handoff.py` crashed with ImportError
   (venv namespace shadow) and session-setup.sh line ~461 mislabeled rc≠0 as "DURABLE THREAD LEASE
   CONFLICT". Audit every hook branch that maps an exit code to a verdict: which ones can report a
   WRONG verdict on crash (vs "could not determine")? List each with file:line.
5. **Redundancy across hooks.** thread-lease-heartbeat, goal-driver-stop, release-thread-lease,
   context-monitor, post-compact — overlapping responsibilities? Same data fetched multiple times
   (e.g. Monitor API curls without If-None-Match/caching)?
6. **Bloat verdict.** For each hook: load-bearing (guards a real burn — cite which) vs bloat
   (removable/mergeable with measured saving). Ranked list of the top wins by saved latency and
   saved context tokens, with concrete recommendation each.
