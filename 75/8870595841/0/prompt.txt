## What to build

1. New route in `scripts/api/epics_router.py` (same file, same router — do not create a new
   router module): `GET /api/epics/graph/v1`. Response shape is fully specified in design doc
   §4.1 — follow it exactly, including the `"id": "area:<id>"` / `"id": "epic:<number>"` node-id
   convention, the `last_state`/`last_decision`/`last_next_action` pass-through from the existing
   `/api/epics/v1` row shape, and the capped `issues_by_epic` shape
   (`{"items": [...], "total_open": N, "truncated": bool}`, 50-item cap per epic).

2. **Mirror `GET /api/issues/streams`'s caching pattern exactly** (`scripts/api/issues_router.py`,
   the `issues_streams` handler and its `_load()` closure) — design doc §4.3 names this as the
   literal implementation to copy the shape of, not paraphrase: `audit.read_cache(max_age_s=3600)`
   first, `read_cache(max_age_s=7*24*3600)` stale fallback with a `"stale": true` marker,
   `schedule_refresh(force=fresh)` only on a genuine cache miss or explicit `?fresh=true`, and the
   whole thing off the event loop via `asyncio.to_thread`. Do NOT call `fetch_epic_membership()`
   or any other live-`gh` function inline on the request path.

3. **`classify()` addition** (`scripts/orchestration/issue_stream_audit.py`, the function that
   builds the cached report): it already computes `titles = {i["number"]: i["title"] for i in
   open_issues}` locally but only re-embeds it for orphan/multi-homed entries. Add a new
   top-level key to the returned report dict, e.g. `"open_issue_titles": titles`, so the graph
   endpoint can build `issues_by_epic`'s per-issue `title` field from the cache without an inline
   `gh` call. This is a small, additive change to an existing function — do not restructure
   `classify()` beyond adding this one key. Existing consumers of the report dict (e.g.
   `scripts/api/issues_router.py`'s `_strip_private_index`) must not break — check whether the
   new key needs stripping there too (it is not private data — issue titles are already public —
   but confirm `_strip_private_index` doesn't choke on an unexpected key).

4. **Area layer**: assemble from `scripts/config/issue_streams.yaml` directly (13 streams, 18
   epic slots) — NOT `scripts/config/fleet_taxonomy.yaml` (design doc §2.1 explains why: it's
   stale, missing the monitor area entirely). Do not "helpfully" reconcile the two registries in
   this PR — that's tracked separately as #7306, out of scope here.

5. **OPSEC sweep update** (`tests/api/opsec_sweep/registry.py`) — binding, design doc §5:
   - `FROZEN_HTTP_OPERATION_COUNT` (currently 280) increments by 1.
   - `FROZEN_DENOMINATOR_SHA256` changes — re-derive it from the sweep's own digest function
     against the updated route table; do not hand-compute it.
   - Add an `isolated` fixture-reason entry for the new route, same pattern and same underlying
     reason as the existing `"GET /api/epics/v1": "isolated fixture has no seeded epic registry
     snapshot"` entry (`registry.py:63`).
   - Run the full sweep (`tests/api/opsec_sweep/`) and confirm it stays green with the updated
     frozen values.
