### r1
## Design note — per-host project state + serving-SHA drift (M4, for cross-family critique)

**Facts (tool-read).** The API runs from an immutable release `.runtime/api/releases/<sha>` (`scripts/api/release_snapshot.py`), while `LIVE_REPO_ROOT` is the mutable checkout on the same host (`scripts/api/config.py`). `/api/health.instance` today reports `git_sha = git rev-parse HEAD` of the process cwd and `host = MONITOR_INSTANCE_ID or socket.gethostname()` (`scripts/api/main.py` `_health_instance_identity`). So (a) `git_sha` is the *checkout* head, not the *serving* release — the merged-but-not-redeployed class (#M-19) is invisible by construction; (b) with the env unset the route leaks a hostname (M5 #7182 class). Cross-host facts reach the API two ways today: pull (atlas-job load via `job_host_exec`, SSH from the API host) and push (`POST /api/observer/presence`, allowlisted agents, TTL). Nothing reports checkouts, worktrees, dirty state, or services with their serving SHA, on any host.

**Proposal.**
1. **Serving identity, per process.** Derive `serving_sha` from the release directory name (`RELEASE_SHA_RE`), else `null` with `serving_mode: "checkout"` (dev). `/api/health.instance` gains `serving_sha`, `serving_mode`, `checkout_sha`; `git_sha` stays as a documented alias of `checkout_sha`; `host` becomes the opaque self host id (the #7246 resolver; `local` if unresolvable) — no hostname fallback anywhere.
2. **Per-host reporter (push, like observer presence).** A read-only collector `scripts/api/project_state_local.py` runs on each host on a timer (systemd timer on the Linux hosts, LaunchAgent on the notebook — same cadence class as presence, 5 min) and POSTs one sanitized document to a loopback-only `POST /api/fleet/projects/v1/report` (allowlisted reporter identity, TTL 15 min): `host_id` (opaque), `primary: {head_sha, origin_main_sha, origin_main_age_s, ahead, behind, dirty_count}`, `worktrees: {count}`, `services: [{name, state, serving_sha}]` (from the existing `services.sh status` semantics plus each service's release dir), `collected_at`. The API host reports itself in-process (no timer needed). No absolute paths, hostnames, ports, or SSH aliases in the document; the collector strips them at the source and the API rejects any that slip.
3. **Read route + panel.** `GET /api/fleet/projects/v1` → per opaque host: the last report, `age_s`, `freshness: fresh|stale|unknown` (stale > 15 min, unknown when never/expired — never rendered as "in sync"), and per service `drift: true|false|unknown` where drift = `serving_sha != origin_main_sha` of the reporting host, plus an `attention` list (drift, dirty primary, stale report). `fleet.html` gains a "Projects" panel (one row per host, services inline, drift badge); `/api/occupancy` is untouched.
4. **Contracts/docs/OPSEC.** Route + page registered in `route_contracts`; `docs/MONITOR-API.md` documents freshness window and drift semantics; the M5 sanitizer test covers the new route and the changed health field; unit tests per collector field with fixtures (no live git/SSH), drift matrix (equal / behind / unknown), TTL expiry ⇒ `unknown`.

**Rejected.** *Pull via SSH from the API process* (job_host_exec) — puts SSH aliases and a network dependency inside request handling; the atlas-load pull is a legacy exception, not the pattern. *Extending `/api/occupancy`* — different cadence and contract (load/seats); keep one glance by placing the panel beside it in `fleet.html`.

**Open for critique.** (i) push vs pull; (ii) `origin_main_sha` source — local `origin/main` ref + FETCH_HEAD age (no network in the collector) vs an explicit `git ls-remote` (network + creds on a timer); (iii) whether `services.sh` can expose each service's serving release dir without a second source of truth; (iv) reporter identity/allowlist shape vs reusing the observer-presence allowlist.

**Acceptance (issue).** Merge a trivial PR without redeploying → `drift: true` on the api service within the freshness window; restart → clears; no absolute paths or hostnames in the output.

### r2 (binding)
## Design r2 — with the cross-family critique folded in (Gemini seat, task `critique-7188-design-agy`: PASS-WITH-CHANGES, 5 findings; push + local-ref + cwd-inspection + host-id allowlist all confirmed). Design of record for implementation.

Binding changes on top of r1:
1. **Conditional drift.** Per service: `state != running` ⇒ `drift: "unknown"`; `serving_mode: "release"` ⇒ compare `serving_sha` with the host's `origin_main_sha`; `serving_mode: "checkout"` (dev/`--live`; today `sources` and `astro` always run from the checkout) ⇒ compare `checkout_sha`, badged "checkout" in the UI. Never `null != sha ⇒ true`.
2. **Sibling repositories.** `work` runs from a separate private checkout; its SHA is never compared with this repo's `origin/main`. Each service reports `repo: "learn-ukrainian" | "sibling"`; sibling services get `drift: "not_applicable"` (their own checkout state may be reported later under their own repo key).
3. **Upstream staleness guard.** `origin_main_sha` comes from the local `refs/remotes/origin/main` (offline); `origin_main_age_s` from `.git/FETCH_HEAD` mtime. `origin_main_age_s > 3600` ⇒ every drift on that host degrades to `"unknown"` with a `stale_upstream` attention item — never a green "in sync" from a stale ref.
4. **Serving dir from the process, not from `services.sh`.** `services.sh` has no notion of release dirs; the collector takes each verified listener PID's cwd (`/proc/<pid>/cwd` on Linux, `lsof -p <pid> -d cwd` on macOS) and classifies it with `scripts/common/release_layout.is_release_root()`; the api service additionally exposes `serving_sha` on `/api/health`.
5. **Reporter identity = opaque host id, not the observer agent allowlist.** `POST /api/fleet/projects/v1/report` accepts only `host_id` values that pass `occupancy_sanitize.opaque_host_id()` and appear in `MONITOR_OCCUPANCY_HOST_IDS` (plus `mac-operator`); loopback-only; TTL 15 min. `observer_presence.ALLOWED_AGENTS` stays for seats.
6. **Transport stated.** The API host evaluates itself in-process (no network). Other hosts report over the existing loopback tunnel; a host without an active tunnel simply never reports and shows `freshness: "unknown"` — fail-closed, no SSH from the API process. Deliverable includes the collector CLI, unit/LaunchAgent templates, and a runbook section; deploying the timers is an operator/infra step, not part of the PR.

Unchanged from r1: `/api/health.instance` gains `serving_sha`/`serving_mode`/`checkout_sha`, `git_sha` kept as alias, `host` = opaque self id (no hostname fallback); `GET /api/fleet/projects/v1` per-host document + `attention`; `fleet.html` Projects panel; `/api/occupancy` untouched; route + page contracts; M5 sanitizer test over the new route and the changed health field; fixture-only tests (no live git/SSH) including the drift matrix (release-equal / release-behind / checkout / stopped / sibling / stale-upstream / never-reported).
